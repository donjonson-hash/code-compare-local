A LITTLE HELP FOR YOUR NEXT CHANGE

Compare. Review.
Keep your work.

Start with two versions of a file. Compare Code shows their differences and lets you choose which changes to keep, all in your browser.

From two files to your result

  1. Open or paste both versions. Put your reference in A and your result in B. Both fields are editable. Opening a file selects a language; the language setting applies to both fields.
  2. Choose a difference. Use the Differences list or Previous/Next. Use A → B copies the selected block into B. Keep B marks a block reviewed without changing its text.
  3. Review your changes. Undo and Redo affect B. Ctrl/Cmd+Z works in the focused editor. All A → B replaces the complete result and can be undone.
  4. Save and check. Set the result filename and choose Download B. Open the downloaded file again to check it. Download B saves only B; keep any edits to A separately.

Only changes folds unchanged sections. Show spaces & tabs makes whitespace visible without changing it. Code size and Wrap lines adjust the view. Focus mode gives the editors more room while preserving both texts and their history.

What syntax checking covers

Checks run automatically after edits for supported languages. You can also select Check syntax and click a reported location to jump to it.

LanguageCheck available
JavaScript / JSXSyntax parsing; code is not executed.
TypeScript / TSXSyntax parsing without type checking.
JSONJSON syntax.
YAMLSyntax without schema validation.
PythonPreliminary grammar and indentation checks; verify the result with Python itself.
HTML, CSS, Java, C/C++, SQL, MarkdownHighlighting only.

Each side is checked as a complete file, so an incomplete snippet can produce errors. Clean syntax does not prove correct logic, working imports or a safe program. Compare Code does not run your code.

Some diagnostics offer a Preview fix button. Review the before and after text, then apply the edit to its indicated side or cancel. Only a small set of conservative edits that pass another parser check are offered; this is not a general code repair tool. Applying an edit triggers a new syntax check. Use Undo for B, or focus A and press Ctrl+Z (Mac: ⌘Z) to undo an edit in A. If the code or language changes while the preview is open, close it and check again.

Syntax: before & after compares diagnostics in A with the current B. It separates newly reported issues, issues no longer reported, matching issues and uncertain matches. Click a location to open it in A or B. A parser can stop at an early error, so an issue no longer reported is not proof of a fix. Incomplete or unsupported checks do not produce a successful comparison.

Files and limits

  • Open UTF-8 text files up to 512 KiB (524,288 bytes) per file.
  • Each editor supports up to 200,000 UTF-16 text units and 4,000 lines. Some emoji and other characters use two text units.
  • Downloads preserve the original LF, CRLF or CR line endings, mixed line endings and UTF-8 BOM. New lines you type use that file's main line-ending style.
  • Comparison includes spaces, tabs and the final newline. Large differences may be grouped into broader blocks.

The workspace compares two texts. It does not compare folders or whole projects, connect to Git repositories, or perform a three-way merge.

Common questions

Why is there a warning after I download?

The page cannot confirm that your browser finished saving the download, and Download B does not save changes in A. Check your saved file and keep anything you need from A before leaving.

Can I continue a saved session?

Click Save session before leaving, then use Open session to load the downloaded JSON file later. Both texts, filenames, language, view settings and remaining Keep B marks are restored. Applied edits are already part of B; historical review counts and Undo/Redo history are not restored. There is no automatic recovery after closing a tab.

Session files contain your code without encryption. Opening one replaces the current workspace after confirmation. Invalid files leave your work unchanged. A session can be up to 8 MiB, with each document within the usual file limits. Save session retains the leave-page warning because the browser does not confirm a completed save.

Why won't my file open?

Check the file size, line count and encoding. Save it as UTF-8 text first. Binary files and files over the stated limits are not supported.

Copy B is unavailable, or formatting changed.

Your browser may restrict clipboard access. Download B instead, or select and copy B manually. Clipboard transfers may alter line endings; downloading preserves them.

Syntax checking is incomplete.

Choose a supported language and try Check syntax again. If checking remains unavailable, save both texts before reloading the page. Treat an incomplete check as unverified.

Does the website work offline?

It needs a connection to load its files. Comparison and syntax checks then run locally. Reloading or opening a new page offline is not guaranteed.

Report a problem

Use the project's GitHub issues. Include your browser and operating system, the steps to reproduce the problem, what you expected and what happened. A small invented example is usually enough.

Issues are public. Remove private code, credentials and personal data from examples or screenshots before posting. The application does not send a report for you. See Privacy for details about local processing and website requests.
