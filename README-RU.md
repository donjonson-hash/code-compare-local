# Code Compare Local · бета 0.6.1

## Пилот проверяемых правок

Версия 0.6.1 сохраняет для каждой показанной правки A → B версии обоих
документов и ожидаемый исходный текст. Перед переносом проверяет их
актуальность, применяет правку целиком и блокирует повтор той же команды.
Двойное нажатие не переносит следующий блок. Отмена и повтор сохраняют
точные байты и прогресс просмотра; после отмены создаётся новая правка.

Описание операций и контракта: [DETERMINISM.md](DETERMINISM.md).
Это отдельный пилот разработки. Материалы в `store/` подготовлены для
проверенной версии 0.5.0 (коммит `7de941c`).


Отдельное расширение для локального сравнения кода. Без LLM, платного API,
аккаунтов, сервера и доступа к вашим чатам. Интерфейс беты — на английском.
[English instructions](README.md) · [Обработка данных](PRIVACY.md).

Кнопки **Use A → B**, **Keep B**, **Undo**, **Redo** и **Download B** находятся
вместе над редакторами. В версии 0.6.1 исправлено обрезание кнопок карточек
на узком окне; Undo и Redo получили видимые текстовые подписи.

## Установка в Chrome / Chromium / Edge

1. Распакуйте архив в постоянную папку.
2. Откройте `chrome://extensions` (Edge: `edge://extensions`).
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное расширение** и выберите папку
   с файлом `manifest.json`.
5. Закрепите расширение в меню браузера и нажмите его значок.
   Редактор откроется в отдельной вкладке.

Node.js и сборка для установки не нужны: `app.js` и `syntax-worker.js` уже включены в архив.
Это распакованная бета, не опубликованный или одобренный магазином выпуск.
Сборка предназначена для настольного Chromium; Firefox в этот выпуск не входит.

## Первый сценарий — за минуту

1. Нажмите **Try example** или загрузите два файла в A и B.
2. A — исходный код; B — новая версия и будущий результат. Оба поля редактируются.
3. В списке **Differences** сразу видны номера строк A и B. Нажмите карточку,
   чтобы открыть этот участок в обеих версиях. **Previous / Next** переключают
   различия; **Use A** переносит только выбранный блок из A в B.
   **Keep B** оставляет код B и отмечает блок проверенным. После решения
   открывается следующее непроверенное изменение; **Reviewed X / Y** показывает
   прогресс, включая уже перенесённые блоки.
   Стрелка **→** между редакторами также работает.
4. Внесите дополнительные правки прямо в B. Кнопки ↶ / ↷ отменяют и повторяют
   изменения в B. Ctrl/Cmd+Z действует в текущем редакторе.
5. Укажите имя файла с нужным расширением и нажмите **Download B** («Скачать B»).

**Code size** меняет размер кода: 14, 16, 18 или 20 px, по умолчанию 16 px.
После загрузки файла открывается первое различие; пустые файлы тоже поддерживаются. При удалении
или добавлении текста в противоположной версии показана точка вставки.

**Only changes** сворачивает длинные одинаковые участки, оставляя три строки
контекста. Нажмите маркер скрытых строк или выделите его клавишей Tab и нажмите
Enter/Пробел — участок раскроется в обеих версиях. Отключение режима показывает
полные файлы. Нажатие на ошибку синтаксиса раскрывает полный файл, чтобы ошибка
в одинаковом участке также была видна.

**Show spaces & tabs** показывает пробелы точками, табуляцию — стрелками.
Файл не меняется. Метка **Spaces / tabs changed** обозначает изменение этих
символов, а не его безопасность: отступы Python и пробелы внутри строк значимы.

Отмена/повтор **Use A** восстанавливает прогресс просмотра. Ручное изменение
текста сбрасывает отметки: проверяется уже новая версия. **Keep B** — отметка
просмотра, а не правка; обычная отмена текста её не снимает. Загрузка файлов,
примера и очистка начинают новый просмотр. Между сессиями отметки не хранятся.

Кнопка **All A → B** заменяет весь результат исходной версией. Доступна отмена.
**Copy B** копирует текст в буфер обмена; точные байты переносов строк
и BOM сохраняются именно при скачивании.

## Проверка синтаксиса

После загрузки, вставки, ручной правки, переноса блока и отмены расширение
автоматически проверяет обе версии. Кнопка **Check syntax** запускает
проверку повторно. Выбранный язык применяется к A и B; расширения .jsx и .tsx
автоматически включают отдельный режим JSX/TSX.

- **JavaScript / JSX / TypeScript / TSX:** синтаксический разбор, без проверки типов.
- **JSON:** строгий синтаксис — в том числе пропущенные значения, запятые и скобки.
- **YAML:** синтаксис, отступы и дубликаты ключей, без проверки схемы.
- **Python:** предварительная проверка грамматики и отступов, включая пропущенный,
  лишний и несовпадающий отступ, неоднозначное смешение табов и пробелов.
  Это не полноценная проверка CPython: контекстные ошибки и часть конструкций
  могут остаться незамеченными. Заголовки `with (…)`, не поддержанные
  грамматикой парсера, отмечаются предупреждением для проверки в Python.
- **Другие языки:** только подсветка, с явным сообщением об отсутствии проверки.

Ошибки отмечаются в редакторе. Нажатие на сообщение под соответствующей
версией переводит курсор к строке. Проверка не меняет исходник, не форматирует
код автоматически и не препятствует сохранению незавершённого фрагмента.

Оба текста рассматриваются как самостоятельные файлы. Например, отдельный
`return` без функции может быть диагностирован как ошибка JavaScript.
Синтаксически допустимая смена вложенности Python может изменить поведение
и не считается синтаксической ошибкой. В JavaScript обычное изменение отступов
также не обязательно означает ошибку.

Парсеры работают в отдельном локальном Web Worker, без сети и выполнения
вашего кода. Старые результаты скрываются сразу после изменения текста.
Если проверка не завершилась за 3 секунды, выводится сообщение, а не статус
успеха. За один проход показывается до 50 сообщений на редактор.

Для обновления замените файлы установленного пилота содержимым нового
архива и нажмите кнопку обновления у расширения в `chrome://extensions`.
Затем заново откройте его вкладку, предварительно сохранив текущие тексты.

## Сохранность данных

- Обработка происходит внутри вкладки. Расширение не запрашивает разрешений
  на сайты, не содержит аналитики, внешних шрифтов или сетевых API.
- CSP запрещает сетевые подключения и выполнение загруженного кода.
- Код хранится в оперативной памяти вкладки. После закрытия, обновления страницы
  или перезапуска браузера сессия не восстанавливается. Скачайте результат заранее.
- Оригинальный файл на диске не перезаписывается: браузер скачивает новый файл.
- Сохраняются табуляции, пробелы, завершающий перенос, UTF-8 BOM, LF, CRLF, CR
  и смешанные переносы в неизменённых участках. Скопированные блоки сохраняют
  переносы A, вручную введённые строки используют основной формат B.
- Если тексты совпадают, а различается только формат переносов/BOM,
  появляется отдельное уведомление и кнопка переноса формата A → B.
- Буфер обмена и исходный чат могут нормализовать переносы. Для побайтового
  сравнения исходных файлов используйте загрузку файлов и скачивание.

## Границы беты

- Два текстовых файла UTF-8, каждый до 512 КБ, 200 000 символов UTF-16
  и 4 000 строк. Двоичные файлы и другие кодировки отклоняются.
- Подсветка JavaScript/JSX, TypeScript/TSX, Python, JSON, HTML, CSS,
  Java, C/C++, SQL, YAML, Markdown и обычного текста.
- Сравнивается текст. Нет проверки логики программы, объяснения алгоритмов,
  исполнения кода, проектов с множеством файлов или работы с Git.
- При очень больших различиях ограничение времени алгоритма может давать
  более крупные блоки. Это отмечается словом «grouped»; текст не теряется.
- Нет автоматического извлечения ответов ChatGPT / Claude / Gemini:
  первая версия использует ручное копирование и загрузку.
- Нет хранения истории между сессиями, монетизации и лицензирования покупок.

## Разработка

Исходники находятся в `src/`, регрессионные проверки — в `tests/`.
Зависимости закреплены в `package-lock.json`. Нужен Node.js 24+.

```sh
npm ci
npm run build
npm test
npx playwright install chromium
REQUIRE_EXTENSION=1 npm run test:browser
npm run package
```

Для пользовательского сценария используется CodeMirror 6 MergeView.
Модель сохранения точных переносов и BOM написана отдельно.
Проверки синтаксиса используют Babel Parser, Lezer и YAML; исходники проверок
находятся в `src/syntax.mjs`, управление фоновыми проверками — в `src/syntax-ui.mjs`. Принцип работы
взят из обсуждения Compare These Texts. Его репозиторий был просмотрен
на коммите `f164cf503c79e034c4ade8e345dbf9cbccbd5829`; исходные файлы CTT
в этот самостоятельный пилот не копировались и не изменялись.

Сторонние лицензии находятся в `THIRD-PARTY-NOTICES.txt`.

## Короткая проверка беты

Используйте небольшой пример без личных и конфиденциальных данных:

1. Откройте правильный файл в A, а его копию с одной ошибкой синтаксиса — в B.
2. Убедитесь, что ошибка появляется в B и нажатие на сообщение открывает
   соответствующую строку.
3. Перенесите исправление A → B. Ошибка должна исчезнуть.
4. Отмените изменение — ошибка должна вернуться. Повторите изменение.
5. Скачайте B под новым именем. Снова откройте скачанный файл в B и проверьте,
   что исправление и отступы сохранились.

Если шаг не сработал, запишите версию расширения и браузера, выбранный язык,
шаги воспроизведения, ожидаемый и фактический результат. Для разбора достаточно
минимального примера, которым вы готовы поделиться. Расширение автоматически
не отправляет обратную связь или код.

Для оценки удобства запишите, удалось ли закончить реальную задачу без
перехода в другой редактор, какое действие было непонятным и понадобилось ли
расширение для следующей задачи. Один успешный тест ещё не подтверждает
повторное использование.

Для разработки используйте архив исходников. В установочном ZIP находятся
готовые файлы расширения. В `examples/` есть пары правильных и ошибочных файлов
для пяти языков. Перенос репозитория описан в `REPOSITORY-SETUP.md`.
