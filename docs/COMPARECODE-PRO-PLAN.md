## Проверка WebKit для сайта — завершена

На коммите `40eb611f599c232f94769207734d112f0c580c93` прошёл полный набор
сценариев сайта в WebKit 26.5 на Linux:
[CI WebKit](https://github.com/donjonson-hash/code-compare-local/actions/runs/42793697775/job/129753300229).
Проверены загрузка A/B, переносы, Undo/Redo, скачивание и повторное открытие,
точные BOM/LF/CRLF/CR, сессии, синтаксис и Preview fix, отмена ухода и узкое окно.
Ни одна функциональная проверка не пропущена.

Команда: `npm run test:web:webkit`; отдельный job `Website / WebKit` выполняется
в CI вместе с прежними проверками Chromium. Сетевой режим WebKit — блокировка
HTTP(S) с локальной копией скрипта worker, поскольку эмуляция offline ломает
чтение File API в тестовом окружении. Причина и воспроизводимый диагностический
скрипт описаны в `WEBSITE-LAUNCH.md`. В указанном успешном прогоне приложение
не обращалось к HTTP(S), а локальная копия worker не потребовалась.

### Оставшиеся задачи сайта

- Нативная проверка Safari/macOS или iOS остаётся неподтверждённой: Linux/WebKit
  не является проверкой этих устройств и не подтверждает их offline-поведение.
- Search Console submission **не выполнен**: требуется проверенная property
  домена и отправка `https://comparecode.pro/sitemap.xml`.
- Выпуск расширения остаётся отдельной задачей вне текущего объёма.

Подробности production и оставшихся проверок: `WEBSITE-LAUNCH.md`.

### Этап 3 — проверить пользовательский сценарий

Основной сценарий для сайта и установленного расширения:
загрузить A/B → найти различие → перенести выбранный блок → Undo → Redo →
скачать B → открыть скачанный файл → проверить содержимое и байты.

Дополнительно:
- Ошибка синтаксиса появляется и исчезает после исправления; устаревшие результаты не отображаются.
- BOM, CRLF/LF/CR, Unicode, пустой файл и завершающий перенос не теряются.
- Двойное нажатие и устаревшая правка не затрагивают следующий блок.
- Only changes, Keep B, клавиатура, узкое окно и масштаб не скрывают основные кнопки.
- Проверить Copy B, загрузку и экспорт в Chromium и WebKit для сайта; Chrome/Edge для расширения.
- Проверить отмену скачивания: сейчас Download снимает dirty сразу после link.click(), что требует проверки предупреждения о несохранённых данных.
- Проверить сетевые запросы: пользовательский код не покидает браузер.
- Повторно использовать существующие содержательные тесты; добавлять регрессии только для новых рисков/найденных ошибок.

Критерий готовности: CI и основные сценарии проходят на точном коммите кандидата;
реальное скачивание подтверждено, а не только наличие кнопки.
