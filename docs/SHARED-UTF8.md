# Общий кодировщик UTF-8

Первый адаптер к Deterministic Extensions переиспользует только преобразование байтов UTF-8 и начального BOM. Модуль хранится без изменений в `src/vendor/deterministic-extensions/utf8.mjs`; источник, полный коммит и SHA-256 записаны в соседнем `provenance.json`. Сборка проверяет контрольную сумму перед включением модуля в `app.js`. Во время работы и сборки загрузка кода из GitHub не требуется.

В `src/document.mjs` остаются правила Code Compare Local:

- входной файл до 512 KiB;
- до 200 000 UTF-16 единиц после нормализации переносов и до 4 000 строк;
- отказ от текста с NUL и прежние сообщения об ошибках;
- выбор доминирующего переноса строк и сопоставление raw/нормализованных смещений;
- существующие правила изменения блоков, Undo/Redo и форматирования.

Это важно: общий документный слой системы использует другие лимиты и проверяет корректность UTF-16. Он здесь не подключён. Низкоуровневый кодировщик использует стандартное поведение TextEncoder для одиночных суррогатов; Code Compare Local сохраняет прежнее поведение ручного текста. Для корректных входных файлов UTF-8 импорт/экспорт сохраняет байты, включая повторный U+FEFF после BOM, смешанные переносы и последний перевод строки.

## Обновление

1. Выбрать проверенный коммит общего репозитория и изучить изменение контракта `utf8-v1`.
2. Скопировать `src/core/utf8.mjs` без изменений, обновить полный коммит и SHA-256 в provenance.
3. Выполнить `npm run build`, `npm test`, браузерную проверку установленного расширения и `npm run package`.
4. Проверить совместимость на границах лимитов и точные байты после Undo/Redo. Изменения пользовательской политики оформлять отдельно.

Тест `shared-utf8.test.mjs` сравнивает адаптер с зафиксированным прежним поведением на детерминированных наборах входов. Двигатель diff, его политика и синтаксические анализаторы не заменены.
